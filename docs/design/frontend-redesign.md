## 结论与范围

现有 UI 已有相当多的工程守卫和页面规范，问题在于产品任务、规范与实现没有形成统一验收合同：一些规则只约束“用了什么组件/分页/滚动”，不能保证信息层级、可读性和完成任务的效率；个别页面还直接违反已有“实现注释不入 UI”的规则。继续逐处改灰字或按钮位置不能完成全站重设计。

平台最高原则是**数据聚合 + 安全全生命周期管控**。前端聚合专业平台数据、展示来源/更新时间/深链，并组织本地风险与工单生命周期；SOC/CMDB/TIP/SOAR/AI专业能力以接入、消费、跳转为主，不复制其专业分析与运营产品。建议保留 Vue/Element Plus、ProTable、请求会话隔离、表单/流程适配器等可复用资产，先形成产品信息架构、设计 tokens、页面模式、全部页面迁移表和状态样本，再按批次改造。**不建议仅为美观先更换组件库或重写 SPA**；是否保留四种导航布局、固定视口等旧设定列为本轮设计决策，允许重审，不把历史拍板当永久技术约束。

静态盘点覆盖 `src/views/` 下 27 个路由视图文件（包括会话/错误/重定向页），另读 LoginForm、IntelResult、壳层/路由、ProTable、FilterBar、NavbarBadge、UserPicker、附件、富文本草稿、字段设计器与流程设计器。27 是文件盘点数，不是“27 页已在浏览器验收”。逐页职责、证据、发现、任务、验收见[逐页清单](frontend-pages.json)。

新设计与未绑home专用场景的后续浏览器验收需安排独占环境；普通用户和空菜单场景应使用专属合成账号 E000002+，不改 E000001。大量 mock 是用户明确保留的工程能力；改造计划新增丰富的合成状态样本，并保留关键真实栈验收。mock 不能用于证明后端资源授权正确。

## 发现与建议

### FE-PRE-01：普通角色的公共首页与导航合同不成立（P1，条件性静态缺陷）

证据链：`src/components/Logo/index.vue` 的 RouterLink 固定 `to="/"`；`src/router/index.ts` 的 `constantRouterMap` 固定根重定向 `/home`，但 `/home` 只由菜单生成；主仓 `MenuService.GetUserMenus` 对无有效角色直接返回空列表，否则通过 `MenuRepo.ListByRoleIDs` 的 `role_menus` JOIN 取菜单；祖先补链不会补入无关的 home。`000002_seed.up.sql` 只给 admin/superadmin 全绑菜单。未绑定 home 的自定义角色因此没有 `/home` 动态路由，Logo 的固定目标会落 404。`Error/404.vue.errorClick` 在空动态路由时回 `/`，又可能回到相同错误页。

现有 `routing.test.ts` 的 viewer 测试主动传入 homeMenu；`e2e/global-setup.ts` 又明确给 viewer/operator 角色附加 home.id，所以这些绿色场景不能证明普通自定义角色边界成立。**尚未用真实账号复现用户当前遇到的实例；不能把条件链路直接宣布为该实例唯一根因。**

推荐合同：将公共工作台作为身份自服务入口，路由不依赖业务菜单授予；导航显示与路由注册使用同一来源，避免同 path 双注册。工作台默认只消费该身份允许的自服务数据；工单、任务、统计面板需要各自能力判断及服务端授权，不因首页公共化而开放数据。Logo、403 返回、404 返回、登录默认落点、关完页签后落点统一解析到安全默认页。`NavbarBadge.goTodo` 当前也始终跳业务动态路由 `/tickets`，全局入口需一起核查有无可达目的地，不能只修Logo。无有效角色时应按 IAM 既定策略显示“尚未分配业务权限/联系管理员”或进入专用引导，不悄悄授予角色；这一边界需与后端 SelfService 对无角色的处理共同确定。

验收：自定义角色不绑 home、只读角色、只有个人权限、组织继承角色、角色被禁用/撤销、空业务菜单分别登录和刷新；点 Logo/403/404 返回/关闭所有页签均有稳定目的地，零导航循环；无权限域零请求、零数据泄露。mock 先重现菜单响应边界，再用真实专属账号验证。

### FE-PRE-02：首页是工单仪表盘，尚非跨域个人工作台（P2，现状与产品规划）

`views/Home/index.vue` 有六张工单卡和最近工单，不能认定“根本没有首页”。`onMounted` 固定发起状态、我的待办/已办及最近工单请求（四状态 + 三个我的状态 + 最近，共八次工单列表调用）；失败分支将统计置 0、最近列表置空，没有区分“确实为零”与“不可用”。无工单读能力时也缺少请求门控。

主仓 `docs/phase6/08-home-workbench.md` 已有身份条、跨域合并卡和角色渐进提案；应吸收并修订，不能重复立项。该历史提案把“工单数据面全员可得”等可得性写得过于宽松，必须与真实 L1/L2 校准；不能从本地测试角色都有页面权限外推为所有登录用户。

代表方案：顶层身份/组织上下文与一个最相关主操作；主体按“我的待办/我发起”“消息”“有权限的任务与风险摘要”呈现；管理员态势作为独立区块。少量关键数字配可解释口径和准确深链。失败显示“暂不可用 + 重试”，未授权隐藏并不发请求，空数据提供合法的开始动作。聚合端点与卡片各自排期，不让视觉改造承诺尚未实现的数据。

目前首页、消息待办两态集合与角标“排除终态且含自定义状态”的集合不一致，已有测试刻意维持这种差异。UX1 必须决定是统一领域口径还是使用明确不同名称；修改需要后端域合同和迁移验证，不能只在 UI 偷换过滤条件。

### FE-PRE-03：主操作、工具栏、卡头和文案仍不一致（P2，静态属实）

例证：工单/用户的新建位于 ProTable 单独 toolbar 左侧；分派规则的新建在说明行右侧；活动类型新建在筛选行右侧；通知模板/规则新建在工具行左侧并贴长说明；字典主从两侧各自新建。语义可以不同，但当前缺少“页面主操作/区块主操作/批量操作/行操作”的统一层级，用户需要到不同位置寻找同类操作。

`ticket/rules/index.vue` 直接展示 priority、keyword、target_user、target_org、open，表头“关键词（LIKE）”、表单“决议③”；`ticket/detail` 分派提示有 B1-2；通知配置提示 params.template；设置页底部集中展示内部 key。这些应按受众拆分：日常界面用业务语言，专家模式/诊断详情保留必要技术标识，设计编号与实现过程退出产品文案。

推荐一个 PageHeader/SectionHeader 合同：页面标题与必要摘要形成单一定位；页面主操作固定在标题行末端（批量选择时切换为批量动作条）；搜索/筛选是下方工具区；主从页区块操作紧邻区块。只有多区块或上下文需要才加区块标题，不机械执行“一卡必去头”。分派规则提示改为“按优先级依次匹配，命中后分派到指定组织和处理人”；详细边界置于可访问的帮助入口，不用一行浅灰代码词堆满首屏。

### FE-PRE-04：筛选折叠会隐藏生效条件，缺少语义状态（P2，静态属实）

`FilterBar` 按直接 DOM 子元素顺序隐藏第 K 个以后的控件，只有“展开/收起”文字；没有生效条件计数、摘要、清除单条件，也没有 `aria-expanded`/被控制区域关系。工单页日期/“我处理的”“我发起的”属于后面的隐藏组；从首页/角标深链预填后可能在收起状态继续生效，用户却看不见影响结果的条件。

推荐常用 2–3 项 + “更多筛选（N）”，表格上方始终可见当前条件 chips 与“清除全部”，明确字段标签，不用多个“全部”下拉让人猜维度。控件用配置/schema 语义分组而非靠子 DOM 序号；折叠是呈现状态，不应清除筛选。简单低延迟筛选保留防抖即时查；复杂条件树/昂贵查询允许“应用”，不再把“全站所有筛选必须即时生效”当不可重审规则。URL、keep-alive、表单回显、列表、导出保持同一筛选模型。

### FE-PRE-05：工单列表批量标签是新增能力（P2，跨前后端）

当前 `ticket/list` 只有标签过滤，没有选择列；ProTable 自身未暴露选择列/selection-change 合同。`useCrud` 虽有 selectedKeys，并未接成页面能力。当前 `POST /tickets/tags` 入参是单个 ticket_id + tags[]（最多20个标签，每个50字符），不是多工单批量端点。

主仓 `ticket.Service.AddTags` 逐工单走 read 授权；挂标签/自摘是读可见协作动作，摘别人挂的标签还要求 update；路由在 selfService。批量添加不能为图省事整体改成要求 ticket:update，也不能以页面复选框替代每张工单服务端授权。

首档建议只做“本页显式选择 → 批量添加标签”：保留选择数量、清除选择、限制合理批量大小；切筛选/换域清选择，跨页保留和“全筛选结果”以后作为独立能力，不默认暗选。选择后出现动作条，显示影响数量；提交显示逐项成功/无变化/失败，对失败项可单独重试。优先新增受控批量服务契约复用单项授权与标签清洗逻辑，输入 ID 全程 string；返回对调用者不可见/不存在资源的同形结果，避免泄露存在性；同标签重复提交幂等、保留操作者归属。请求相关性和行级操作结果要可审计，不能宣称跨全部工单原子成功。若首档复用单项 API，也必须限并发、汇总逐项结果、明确刷新/重试语义，不能 Promise.all 后统一 toast 成功。

验收覆盖只读可见可添加、不可见不能添加、部分工单权限变更/删除、已有同名标签、清洗/上限、并发重复、失败重试、只选择本页且全选状态可解释；批量移除另排 U03 / UX2 子项，继承自摘/摘他人差异，不随添加模糊捆绑。

### FE-PRE-06：情报历史的存储语义应先于布局优化（P2）

`intel/query/index.vue` 的历史按 employee_no 存浏览器 localStorage，最多保留500条**成功查询的元数据**，无结果快照，重查会重新调用当前服务；它不是跨端审计历史。stats 的“累计”只是当前保留数组长度，超过500后不是历史累计总数。当前 tabs + 分组树表 `default-expand-all`，组和逐次记录混在同一表，解释文字较多。

推荐桌面主从：左侧窄栏显示“本机最近查询”，搜索、类型/时间、最近查询条目；右侧保留查询输入与当前结果。选历史仅回填并显示元信息，显式“重新查询”才发请求，避免把回看误解为历史快照；结果头清楚标识查询值、获取时间、陈旧/缓存来源。每次执行可进入条目二级详情，不默认展开所有重复记录。窄屏用历史抽屉/独立页签，不强塞双栏。结构化结果优先展示领域摘要，原始 JSON 放专家视图；复制控件有键盘语义。

方案比较：保留 tabs 改善成本最低、适合低频查询；左右栏适合反复查询与切换；列表+详情抽屉适合长历史管理但会压缩宽结果。**初次静态审查时仅提出左右主从候选；同日后续已完成离线原型截图及历史点选/显式重查检查，见[原型说明](prototypes/README.md)与[施工合同](frontend-implementation-contract.md)，不等于生产Vue/真实Provider任务验收或最终版式批准**。UX1/U05仍以同一组合成数据下查找→重查→复制→对照任务核对后冻结布局。跨端历史/服务端查询留痕由 U05 在P6.3入口评审中决定接入既有TI服务、有限本地记录或退出自建，并在主总账登记结果；未实现前明确标“本机最近500条”，不以本地计数充当组织运营指标。

### FE-PRE-07：字体、颜色、密度与空间规则只覆盖一部分（P2，视觉效果待验）

主题变量已经存在；当前可确认的问题是大量直接使用 `text-xs/text-gray-300/text-gray-400` 和独立字号。27个路由视图中，gray-300/400 的字符串出现共77次（词法计数，不是77处视觉缺陷）；登录页有专门字体栈与9–17px等字号，业务页和设计器另有11/12/13px等尺寸。不能未经 computed 样式测量就认定所有灰字都低对比。

UX1 应补 semantic tokens：中文正文建议14px、辅助说明12–13px、区块标题16px、页面标题20–24px及相应行高；它们是待样板页校准的目标值，不是照搬外部系统硬指标。定义文字主/次/弱/禁用、边框/底色/危险/成功等语义，不用灰色深浅承载唯一状态。全站采用同一中西文字体策略，代码/标识符才用等宽。统一间距级差（如4/8/12/16/24/32）、控件高度与表格密度，少量有意义的层级，不用同屏多重卡片阴影叠层。

宽度按任务分：长表格吃满工作区；表单限定可读宽度；主从侧栏在明确上下限内可调，不能一律固定42%或240px；复杂设计器独立工作区。壳层当前60px顶栏+38px页签+50px页脚再加24px内容间距，会与各页二级 tabs/多工具行叠加；UX1 用1366×768、1440×900、1920×1080及200%缩放记录可用内容高度，再决定页脚、页签、双栏导航是否默认保留。禁止未经测量声称“视觉已优化”。

### FE-PRE-08：错误、空态和旧数据状态未形成全站合同（P2）

`useCrud` 已有 listError，ProTable 未在模板消费；请求错误主要靠全局 toast，首次错误可能像空列表，刷新失败可能保留旧数据但无原位失效标记。首页错误变0，消息列表 query 失败后也可落“暂无消息”。`TicketAttachments` 已有原位错误、重试和“已上传但刷新失败”的细分，可作为推广样板。

每个数据面至少区分初始/加载/成功空/筛选空/失败/已有数据刷新失败/无权限。全局错误提示用于知会，持久原位反馈承担恢复；对部分面板失败不要清空整页。对写成功读刷新失败，文案明确保存已成功并提供刷新，防用户重复写入。设计 mock 必须包含这些状态，逐页验收不得只截漂亮的成功态。

### FE-PRE-09：键盘与语义存在确定的静态缺口（P2）

MyOrg 的组织卡、消息/待办行、FormDesigner 的物料和字段卡、IntelResult 的点击复制标量均有 div/span 点击而未提供相等的原生按钮/链接键盘路径；字段排序仅靠拖拽，没有上下移动替代；FlowGraphDesigner 的问题定位也是可点 div。Logo 图片无 alt，compact 模式标题隐藏，需要明确品牌入口 accessible name。LoginForm 的工号/密码主要靠 placeholder 和图标，无显式 label；验证码图片点击刷新缺少键盘操作。Element Plus 内部默认行为不能替代这些自定义外层语义。

已有 Home 卡片 role/link、tabindex、Enter、focus-visible 和 PrimaryNav 原生 button 等正向例子，应保留。UX1 固定交付基础键盘与焦点规则：Tab 顺序、可见焦点、主内容跳转、弹层聚焦/关闭回原触发点、表单错误定位、筛选折叠状态、选择计数状态播报、所有可点击卡/行的键盘等价操作、拖拽的非拖拽替代。详情抽屉/表单固定宽度、窄屏、放大后的可达性需要浏览器验证，静态不能断言必溢出。

### FE-PRE-10：复杂配置被塞进大对话框，未保存状态规则不足（P2）

`ticket/type` 的编辑对话框980px，包含画布/JSON、超时表；字段设计另有多面板与专家表格。应按已拟的流程v2改成独立编辑工作区：列表→版本/发布状态→基本信息/字段/流程/自动动作等导航，属性面板和验证问题就近定位；简单重命名/确认仍用对话框，不强迫所有配置走同一弹层。

现有“详情一律抽屉、动作一律对话框”可保留为默认，但复杂多步动作应允许独立页；视口锁定可以用于工作台/表格，长表单在窄屏/缩放时以内容可达为先，不能把“外层绝不滚动”凌驾于任务完成。系统设置有 dirty bar，富文本有局部草稿，但没有全站通用离开未保存数据合同（本轮在 views 未找到 onBeforeRouteLeave/beforeunload）。需统一离开、页签关闭、重载、切类型、取消的提醒及草稿恢复；不把局部富文本草稿说成完整工单草稿。

### FE-PRE-11：列表、树、主从与人员选择还有跨页一致性债（P2）

- 字典页 `fetchTypes/fetchItems` 固定 page_size100且有显式“异常可静默截断”豁免；新规划应排 UX3 改真分页/穷尽加载并展示总量，不能延续“量小就等用户遇到再做”。左42%宽比例改为按类型名称/搜索需要确定上下限，右侧留足编辑空间。
- 活动列表已有左类型、右数据，能复用主从模式；数据导入是整体替换、空数组可清空，不应为了统一“导入”按钮样式淡化风险。需在向导中展示目标类型、条数、替换范围、确认和结果回执，保留现有危险确认与1MiB限制语义。
- 组织树、菜单树、角色菜单分配要统一搜索、展开、选中、复选级联/非级联说明及可访问性；业务含义不同，不要求所有树都用同一勾选语义。菜单词表只读与角色赋权应保持清楚分工。
- UserPicker 的提示称姓名拼音/工号/用户名，`search` 实际仅按 employee_no 精确与 username 包含查两路并合并，且没有序列号/取消守卫。应校准可搜索字段与响应乱序，失败不能假装“无匹配用户”。它影响工单分派、抄送、催办上级与规则配置。
- Profile 的保存会省略空邮箱/手机，用户清空后保存不能达到清空目的；应与后端 patch 语义一起排 UX3 修订，并保留“未修改/清空/无效”差异。当前是源码可确认的发送行为，不宣称已实测生产问题。

### FE-PRE-12：AI 页面的产品定位与已有 API 接入前提（新增规划）

不增加模型部署、GPU、训练流程，也不建设全能Agent设计器、知识库运营平台、通用脚本市场。规划对象是**既有模型/智能体/知识服务连接**、可用能力引用、凭据引用、场景/数据域约束、使用权限与调用记录。内网场景只选允许的内部模型；其他场景按数据政策和任务选择可调用服务。

建议 UI 分开“连接与能力接入配置/领域Agent配置/会话与计划确认/任务结果”而非一个万能聊天页。智能体采用双轨：外部轨引用既有服务的标识/版本、支持的skill或工具能力、授权范围和调用限额，专业设计/运营回跳原服务；本地轨允许配置平台特有的工单/风险处置领域Agent，使用既有模型API、平台工具白名单、业务模板、提示/skill版本、授权预算与审计，提供受控对话运行面，不扩成通用Agent开发平台或全能画布。结果展示计划、调用回执、来源、耗时/失败和可恢复状态；工单/数据页以有上下文的辅助动作进入。自然语言建单/计划任务必须展示结构化预览、目标组织/身份、时间/时区/重复规则和影响范围，确认后交给既有服务授权执行，不让前端以“AI已确认”旁路权限。查询回答附可追溯来源、数据时间与过滤范围；工具建议/模型生成字段与系统事实有明确标识。知识问答先消费既有知识服务的检索/引用结果，不默认新增知识采集、向量库、文档治理全站。

工单流程、本地生命周期任务协同、外部智能体/自动化运行可共享状态/结果/交接呈现模式，但其状态、执行、审批、持久化和重试语义在领域适配器中分别定义。只有确需本地控制的生命周期环节才增加编辑能力；外部专业流程用运行投影和深链。不能用同样画布外观宣称后端已经统一，更不能把共享UI组件变成新建通用SOAR/Agent平台的理由。此项与总 AI/MCP 架构计划排期对齐。

## 统一页面模式与代表方案

### 全站导航与首页

产品顶层建议按工作对象组织：工作台、工单、风险（实现后开放）、任务、聚合数据/情报；专业平台能力通过对象上下文进入，避免顶层菜单逐个扩成SOC/CMDB/SOAR/AI运营站。系统配置与个人/消息分层，不让普通用户的导航出现无权目的地。四种布局先不同时重画：UX1 选定一套主布局作为验收基线，其他布局明确兼容等级和迁移/退出计划，避免27页×4布局无边界扩大。默认布局选择需基于当前使用习惯与有效内容面积评估，尚未定案。

首页首屏用一个个人待办主区域、消息/近期动作次区域；有权限才出现任务/风险卡。聚合卡区分外部发现/专业分析结果与本地处置生命周期，显示来源平台、同步时间、聚合口径和原平台深链，不把投影说成平台自身分析。首页可留一处“从自然语言开始”入口，但 AI 未配置时不能成为空壳主交互。所有数字旁的数据范围、更新时间与点击目标一致；角色变化和权限撤销刷新后不残留上一用户数据。

### 工单列表与详情

列表上方 PageHeader 右侧新建；下一行关键词+常用维度，更多筛选带生效数量；条件 chips 常驻。表格首列选择，选择后工具区替换为“已选N项/添加标签/清除”，表格密度/列设置保留在末端。标题保持可读详情入口；状态/优先级词表在列表、详情、首页统一。详情主内容为描述、字段、附件、讨论；侧栏为状态、处理人、组织、标签、抄送、时间；动作按当前状态/权限显示并有明确成功/失败反馈。窄屏侧栏叠放，不压缩长文本成细条。最终左右比例需用长标题/富文本/多字段样本验证。

### 情报工作区

桌面优先原型是左历史、右查询和结果；历史是本机成功查询记录，不命名为审计。结果区顶部是查询值、风险摘要（如果 Provider 真有结构化字段）、来源/时间/缓存状态；下方分组详情及可访问复制。没有可映射的 Provider 语义时显示中性的结构化数据，不能凭通用 JSON 臆造威胁评分。趋势移为历史辅助，不占主查询焦点。重复历史默认合并，逐次执行按需展开。

### 管理配置与设计器

普通 CRUD 用统一列表/简单表单；系统设置用分组表单+固定可见保存条；本地类型/流程配置使用独立编辑页、草稿/版本/发布状态和问题列表；模型/外部智能体/知识服务是轻量接入与权限配置，复杂专业编辑回到能力提供方；本地领域Agent用模板化配置表单与版本发布，不建设任意节点/代码的全能画布。通知模板提供变量选择与预览，专家 JSON/模板语法保留在高级区。必要的本地流程图有问题定位、可读列表替代、键盘动作和离开保护。

## 批次与排期合同

以下为建议相对排期，需并入总路线，不是承诺已开工。每项都有固定评审/交付窗口，不再只挂“出现问题再做”。各批都有 UI Owner（前端实施）、Domain/API Owner（涉及权限/数据契约）、QA/集成 Owner 的角色责任；具体人名由执行任务分配。

- **UX0 / U01 / P6.0：入口导航修复批**。先处理 FE-PRE-01，核对无角色策略与真实缺陷复现，建立普通角色/空菜单 mock 样本，验证安全默认落点。首页路由问题不等待全站美术改版。
- **UX1 / U02、U07 / P6.1：设计体系与测试底座**。冻结信息架构、主导航布局策略、tokens、PageHeader/Toolbar/Filter/StateFeedback/SelectionBar合同；比较首页、工单、情报、配置四个代表页原型；引入大量合成 mock 状态、关键组件样例、基线截图与基础 axe/键盘检查，更新旧“不mock”和“a11y等合规触发”的口径。视觉样本由稳定 mock 数据驱动，真实栈仍承担权限/契约/关键链路。英文/i18n骨架在本批明确本轮中文、未来复评窗口及不得漂移的资产责任，不靠“英文用户出现”无限等待。
- **UX2 / U03、U04 / P6.3：工单与配置体验批**。实施列表筛选与批量标签、详情布局、工单创建/复杂配置设计器；流程v2与类型可见性的底层定义/权限合同按主仓先行任务实施，UI配置工作依赖其稳定接口，不把底层能力重复估入U04。批量添加和批量移除拆成有各自验收的子项。AI辅助可能复用的结构化预览/确认组件在此建立。
- **UX3 / U05、U06 / P6.3：情报与全站推广批**。任务/AL/情报/审计/组织/角色/用户/菜单/字典/通知/设置/Profile/MyOrg/消息/登录改密与错误页逐页迁移；修复字典100条截断、UserPicker语义/竞态、Profile清空；情报服务端历史需求在此做契约与排期决策，若总路线分到后续阶段则写明确阶段、依赖和决策期限，当前本机界面先如实标识。逐页清单不得以“共用组件已更新”代替完成。
- **UX4 / A01–A07：对应AI能力同批接线**。A01在P6.2交付只读AI的最小模型API连接/授权/来源与结果呈现；A02在P6.3交付当前用户确认建单的预览与回执；A03/A04在P7交付MCP/自然语言计划任务的结构化预览和确认/回执；A05–A07在P8交付外部Agent/知识/skill接入和本地领域Agent配置双轨、授权范围、受控会话与任务结果。后续P9只消费主仓已定的本地生命周期可靠交接证据，不单独立项通用编排设计站，不复制专业SOAR或通用Agent开发平台。数据来源/模型输出标识、权限撤销、确认/取消/重试作为必验状态。
- **UX5 / U07及各任务验收：每个能力发布候选之前**。27页清单逐项关闭运行待验，真栈角色场景、亮暗主题、截图差异、键盘/焦点/缩放、失败恢复和用户列举问题全量回查；新增页面按同一合同验收。视觉基线更新必须对应设计变更说明，不能默认接受截图差异。

依赖顺序：UX0可先做；UX1是大规模页面改造前置；UX2/UX3可按独立页面与接口并行，但共享组件由一位集成Owner维护；UX4必须在对应后端AI契约稳定后接线；UX5是发布门禁而非末尾装饰。实施估算应按冻结后的页面状态/接口增量拆分，旧“首页纯前端1–2天”等估算不包含当前扩大的权限、mock、全站设计和运行验证范围，不直接沿用。

任务映射以主仓[规划总账](../../../zhuzhao/docs/review/planning-backlog.md)为准：U01导航P6.0；U02设计体系与U07视觉/a11y底座P6.1；U03批量标签、U04配置、U05情报、U06全站P6.3；A01只读AI P6.2；A02确认建单P6.3；A03/A04 MCP及自然语言计划任务P7；A05–A07领域Agent/知识P8。首页公共可达由U01处理，视觉/信息架构在U02冻结，页面改造由总账首页任务与U06协同，不重复估算。P6.E聚合度量消费同一规范，不独立再造BI平台；R01可靠意图底座在P6.1，先于R3与写AI，不被UI批次后移。工作日区间与投入假设由总账统一维护，本文件不编硬日历。高级候选可在相应入口评审中明确退出、保留集成或转外部平台；“全部排期”不等于全部自研。

## 验收方法与证据要求

1. **可控 mock 面**：全部合成数据，覆盖角色、空菜单、长文本、超长列表、未知枚举、慢请求、过期/失败、部分成功、结果乱序；与 OpenAPI/schema/示例契约核对，防 mock 永久漂移。mock 状态用于页面开发、演示、视觉与异常测试，不混入真实业务数据，不外传内部材料。
2. **组件/逻辑面**：筛选折叠不丢生效条件、选择范围、失败重试、string ID、日期/时区、人员搜索响应乱序、草稿隔离；有语义的测试，避免仅镜像实现。
3. **真实栈面**：主仓 L1/L2/L3、角色/组织继承、未绑home、数据可见性、标签逐项授权、任务/AL网关、附件、消息深链；至少admin、operator、viewer、自定义最小角色、组织owner，账号独立合成，不能依赖 globalSetup 给所有角色补 home 才测试。
4. **视觉/可用性面**：关键模式在1366×768、1440×900、1920×1080、窄屏、200%缩放、亮暗模式；长标识符、中文多行、缩放与隐藏导航。正文/提示对比度按实际 computed 前景/背景测量，焦点可见/无遮挡；复杂二维表允许合理横向滚动，不用外层绝不滚动强行裁切内容。截图只能证明像素差异，不能替代任务成功断言。
5. **交付门禁**：每批至少 lint/typecheck/test/audit/build及对应真实栈E2E；后端契约/权限/迁移变更同时跑主仓所需门禁含 make acceptance；报告首轮失败、重试、跳过、未测环境，不能用旧Phase5绿色外推。本轮随后已通过既有六件门禁（244单测/42真实E2E），没有新增设计实现或覆盖率增减结论。

## 参考与适用方式

- [Carbon filtering](https://www.carbondesignsystem.com/building-blocks/core/patterns/filtering)：支持按任务区分即时与批量应用；隐藏筛选要显示已应用数量和清除入口。用于修订本项目筛选合同，不作为更换组件库依据。
- [Carbon data table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)：表格工具栏、显式行选择与选择后动作条可用于批量标签模式；展开明细不必默认全部展开。此处是模式借鉴。
- [Fluent drawer](https://fluent2.microsoft.design/components/web/react/core/drawer/usage)：抽屉适合相关补充内容，复杂长流程需要更聚焦的页面；错误应靠近失败区块。用于重审“一切动作对话框”的绝对规则。
- [W3C WCAG 2.2 quick reference](https://www.w3.org/WAI/WCAG22/quickref/)：按需采用文字对比、缩放/重排、键盘、焦点、标签、拖拽替代和状态消息原则；本文件不宣称完成WCAG合规审计。
- [WAI disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)：展开/收起按钮提供键盘和aria-expanded语义，用于FilterBar组件合同。

公开资料查询日期为2026-11-11；只查询公开设计系统和标准，没有上传项目材料。
