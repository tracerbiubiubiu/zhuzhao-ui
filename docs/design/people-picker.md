# 业务选人合同（F3/CF15）

状态：2026-11-17本地候选已通过组合验证，尚未合入main或部署。验证范围、首次失败及收据映射见[本轮正式报告](../../../zhuzhao/docs/review/reports/audit-baseline-repair-2026-11-17.md)，原材料ID为`maintenance/audit-baseline-repair-20261117/`。

`src/components/UserPicker/index.vue` 按调用方显式上下文选数据源。工单详情的处理人和催办上级用 `assign + ticketId`，抄他人用 `cc + ticketId`；建票催办用 `create-supervisor + orgId + typeCode`，规则目标用 `rule-target + orgId`。真实消费者只有这5处；目前模板无该组件用途。不带业务上下文的管理用途继续调用原 `/users` 管理读，业务403不得回退此接口。

服务端合同唯一归属为主仓 `docs/modules/ticket.md` 的“业务上下文选人”一节，按原动作L1（原本存在时）、L2/L3和候选有效来源判断。规则候选需目标组织有效未过期任职；人工分派/催办/抄送沿现有写合同，不新增同组ACL。响应仅ID和显示标签；用户管理页不因此开放。

输入去空白后须2–50个Unicode字符，最多显示20人。空或1字显示输入提示并发零请求；缺票、缺组织、建票未选类型时禁用并提示补全上下文。合法无匹配、403无权、404对象不可见、网络/5xx/坏载荷失败分别显示，不把错误当空数组。输入新词即可明确重试，不自动重试写入。

`searchSession.ts` 以每次搜索/重置的世代保护实际异步结果、catch和finally；输入新词立即清旧候选，切票、切用途、换组织/类型、组件失活/卸载和下拉关闭使旧搜索失效。票/用途/目标变化清已选ID，关闭下拉只保留当前选中标签，关闭分派对话框清本次选择。`active`由详情页活动态及对话框状态驱动。API层严格校验列表、20项上限、标识精度、标签和去重，畸形响应显示失败。

运行时错序由延迟Promise单测覆盖，输入、无结果/权限/网络错误、关闭重开及切上下文由浏览器专项检查。本轮`e2e/w4-people-picker.spec.ts`的F3已在真实栈用专属普通账号验证：账号有工单动作而无用户管理读权，`/users`在操作前后仍403；可搜索另一名专属目标、完成分派并回读处理人，再添加该目标为抄送人。该证据不借用admin通配权限，也不把故障注入检查当作真实权限验证。
